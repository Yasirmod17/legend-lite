## Beside the homework: the compile phase split over DataCube's model shape
Promised to the DataCube line on 2026-10-10 (their design's §8 and §11): where a page model's compile time goes. The
model is `model-scale.measure.ts`'s `classModel(n)` (a store, a relation function, a class and a mapping per source,
each linked to the next by an association mapped by a ModelJoin), written as text for n = 10 (52 elements) and 200
(1002 elements), compiled 300 times each by a probe (`CompilePhasesProbe.java`: parse by `ElementParser.parse`, then
`Compiler.buildModel`, each timed alone, a line added per run so no model is held already; the JVM, warm, the quiet
machine), under JFR for the split (`jfr_phases.py`: a sample belongs to the outermost phase on its stack).
Medians of the second half (`datacube_phases_*.txt`): n = 10, parse 0.2 ms, build 1.0 ms; n = 200, parse 2.7 ms, build
10.3 ms. The split at n = 200 (378 samples, `datacube_phases_200_jfr.txt`): parse 21 %, resolve 10 %, the index 2 %,
normalize 56 %, element compile 8.5 %, other 3 %; at n = 10 (42 samples): parse 14 %, resolve 14 %, normalize 31 %,
element compile 26 %. So a 200-source page compiles in about 13 ms on the JVM, over half of it in the normalizer
(the mappings' products), and the tab's figures (the WASM module) are a different measurement, the design's own.
