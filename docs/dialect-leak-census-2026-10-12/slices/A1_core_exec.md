### DynaFn (1,298 hits): LANG, and why

`DynaFn.Dialect` is generated by `spec:gen_dynafn`/`DynaFnGenerator` from the engine's `dynaFnToSql` registries. Its only reader in product code is `DynaFn.dialects()`, at one site: `normalizer/RelOpTranslator.java:719`. That site only interpolates the list into the UNSUPPORTED error message. How a name resolves is decided by `Resolution` (`DynaFnDecisions`), never by the dialect set. `spec/.../DynaFnRegistryTest` checks resolutions, not dialects. The list is therefore a mirrored spec table, and no behaviour hangs off it.

## Leak groups (all 13)

### LEAK-SQL

**1. `dropAndCreateSchemaInDb` raw CREATE SCHEMA** (`StatementExecutor.java:2948-2954`)
- **What it does:** the `dropAndCreateSchemaInDb` native builds `"Create schema if not exists " + name`. It sends that text unchanged to the session, with no dialect and no `adaptRaw`, and records the same text for the H2 referee ledger.
- **Why it is a leak:** this is SQL composed outside the dialect, on a path that runs on every backend. SQLite has no CREATE SCHEMA; its dialect renders `SqlDdl.CreateSchema` as `SELECT 1;` (`SQLite.java:2834`). ClickHouse would need CREATE DATABASE.
- **Where it belongs:** `sendEffect(env, env.dialect().render(new SqlDdl.CreateSchema(name)), H2_DDL.render(...))`. `SqlDdl.CreateSchema` already exists (`SqlDdl.java:64`), and `dropAndCreateTableInDb` beside it already uses this pattern (`StatementExecutor.java:2995-3001`).
- **Size:** about 4 lines.
- **Coupling:** none textual. `SqlTextRatchetTest`'s `SQL_SHAPE` does not match `create schema`, so this site is unpinned. `JavaEvalLedgerTest` pins the line count of `StatementExecutor.java` (2298).

**2. `Ddl.insertText` engine-text INSERT** (`setup/Ddl.java:259-290`, hit at :288)
- **What it does:** `setUpDataSqlsText` and `...FromRecords` render CREATE/DROP through `engineText.render(...)`. The INSERT rows, however, are concatenated by hand: `insert into s.t (cols) values (...)`, with `'` doubling and H2's identifier rule `DdlSpelling.h2ExecIdentifier` (:280).
- **Callers:** `SeedSqlForms.assertForm`, `StatementExecutor.java:1106/1119` (plan `testDataSetupSqls`) and `TestDataGenerationNatives.java:118`. According to the `RawSqlBoundary` header, the text is also executed through `executeInDb`→`adaptRaw`.
- **Why it is a leak:** H2-spelled SQL is composed outside the engine-text dialect.
- **Where it belongs:** `engineText.render(SqlDml insert)` or `RowLoad.values()` on the `EngineStyleH2` family, so that the engine-text dialect owns the row spelling.
- **Size:** about 25 lines.
- **Coupling:** `SqlTextRatchetTest` REGISTER `setup/Ddl.java=1` ("the engine-text INSERT rows remain"); `JavaEvalLedgerTest` EVICT_NAMES `Ddl.java`; `TypeSpellingParityTest`.

**3. `Sessions.raisedMessage` `@legend_raise` SQL** (`exec/Sessions.java:123-127`)
- **What it does:** after a failure on MariaDB or MySQL, it runs `SELECT @legend_raise` and then `SET @legend_raise = NULL`.
- **Why it is a leak:** this is MariaDB SQL in the execution-side seam. The protocol is the MariaDb dialect's own; the dialect writes the variable (`MariaDb.java:1868`).
- **Where it belongs:** `SqlDialect.heldRaise()`, returning optional read and clear statements, or `MariaDbConnector.heldRaise(Connection)`.
- **Size:** about 15 lines, together with group 6.
- **Coupling:** `SqlTextRatchetTest` REGISTER `exec/Sessions.java=1`. `TenetRatchetTest` counts its `getString` as a carriage site (15). The caller is `RaisedErrors.unwrapped(e, session)` (:103-106), invoked from seven `Executor.java` catch sites (:55, :91, :111, :177, :235, :267, :301) on every failed statement on every database.

**4. Lowering compares `JSON_TYPE` to DuckDB's json_type names** (`lowering/CanonicalRenderSql.java:934-939, 974-998`)
- **What it does:** the any-cell canon emits `json_type(v) = 'OBJECT'|'NULL'|'VARCHAR'|'BIGINT'|'UBIGINT'|'DOUBLE'|'BOOLEAN'`. The MIR contract of `SqlFn.JSON_TYPE` is therefore "DuckDB's json_type vocabulary", and every other dialect re-maps to it: `Postgres.java:1038-1046` and `BigQuery.java:1536-1541` both say "in DuckDB's json_type vocabulary, which the lowering compares against".
- **Why it is a leak:** DuckDB result values are spelled as string literals in the Lowerer, which is invariant 2's "no SQL in lowering". A 12th database must imitate DuckDB.
- **Where it belongs:** a typed MIR predicate, for example `SqlExpr.JsonKindIs(v, JsonKind.STRING|INTEGER|FLOAT|BOOLEAN|NULL|OBJECT|ARRAY)`, with one render arm per dialect.
- **Size:** about 40 lines of MIR and lowering, plus one arm in each of 11 dialects.
- **Coupling:** `CarrierPurityRatchetTest:141` and `JavaEvalLedgerTest:278` name the file. The same contract has unflagged sites, listed under misses.

### LEAK-ID

**5. SqlTypeCensus dialect-simple-name branches** (`exec/SqlTypeCensus.java:229, 292-295, 551-552, 564-565, 583-584, 606, 615, 640, 647, 660-661, 665-666, 673-674`; key passed at `exec/Executor.java:325-326`)
- **What it does:** `Executor.executePrepared` calls `SqlTypeCensus.probeWire(plan, rs, dialect.getClass().getSimpleName())`. The census then branches on `"Trino"`, `"Snowflake"`, `"SQLite"`, `"MariaDb"`/`"MySql"`, `"ClickHouse"` and `"BigQuery"` by string `equals`.
- **Why it is a leak:** it branches on database identity by dialect class name, outside both seams. A 12th database needs a new `xxxOwn` predicate and a new `dialectSpelling` arm.
- **Where it belongs:** pass the dialect rather than its name, and ask it. Add `SqlDialect.wireVocabulary()` returning `normalizeTypeName(String)`, `ownCarrier(SqlType label, String meta)` and `reportsNoColumnsBeforeFailure()`. A per-driver `DriverCells.wireTypeName` would also fit, since these are driver names.
- **Size:** about 130 lines move into 7 dialects; about 20 lines remain in the census.
- **Coupling:** `DialectBoundaryTest.DATABASE_NAME_DECISIONS` pins `SqlTypeCensus.java=2`, but its regex sees only the `"SQLite"` branches. Other guards naming the file: `JavaEvalLedgerTest:1165`, the `JdbcSurfaceCensusTest` allowlist, `ArchitectureTest:1223-1232` (static CLASSES/SAMPLES), `ErrorShapeGuardrailTest` and `HarnessDisciplineTest`. PCT `ChannelB*Test` and `PctCensusGate` pin its divergence and adopt-pending counts.

**6. `Sessions.raisedMessage` product check** (`exec/Sessions.java:119-120`)
- **What it does:** reads `getDatabaseProductName()` and compares it with `jdbcProduct(MariaDB)` and `jdbcProduct(MySQL)`.
- **Why it is a leak:** it sits inside the SEAM file, but it is an identity compare, not one of its exhaustive per-concern switches. It also runs a metadata call on every failure on every database.
- **Where it belongs:** a per-database capability on the connector (`heldRaise`, see group 3). The executor already holds the session's dialect.
- **Size:** shared with group 3.
- **Coupling:** `DialectBoundaryTest`'s `DatabaseType` regex sees only H2, DuckDB and Postgres, so it does not see this site.

**7. EngineStyleH2 used as the engine-text renderer type** (`StatementExecutor.java:495, 541, 553, 567, 1060-1062`; `PlanEnvelope.java:25`)
- **What it does:** the root layer's toSQLString and plan-text paths type their renderer as the concrete dialect class `EngineStyleH2`, the base of `EngineStyleDB2` and `EngineStyleComposite`. They also cast to it at :1061, which is redundant because `enginePlanText` already returns it.
- **Why it is a leak:** there is no branch. The problem is a concrete, H2-named dialect class used outside `sql/dialect/`. The selection itself already lives in `EngineText`.
- **Where it belongs:** an `EngineTextDialect` interface in `sql/dialect` (render, `collectionSplice`, ...) that `EngineText` returns.
- **Size:** about 12 lines.
- **Coupling:** `ArchitectureTest.engineStyleRendererIsQuarantinedToTheRootLayer`; `DialectBoundaryTest.DIALECT_CONSTRUCTIONS` `EngineText.java=5`.

**8. Default engine plan connection `TestDatabaseConnection(type = "H2")`** (`StatementExecutor.java:770-772`)
- **What it does:** when no connection name can be read, the plan text uses a literal that names H2.
- **Why it is a leak:** the literal duplicates `EngineText.ENGINE_TEST_DATABASE`, which `planDatabase` uses at :1179 and :1078/:1091 spell as `ENGINE_TEST_DATABASE.name()`. The two can drift apart.
- **Where it belongs:** `EngineText.defaultConnectionName()`, derived from `ENGINE_TEST_DATABASE`.
- **Size:** about 3 lines.
- **Coupling:** the `JavaEvalLedgerTest` line-count pin on `StatementExecutor.java`.

### LEAK-TYPE

**9. SqlTypeCensus per-driver wire-type normalization** (`exec/SqlTypeCensus.java:256, 317, 488, 548-723 (*Own predicates and dialectSpelling), 778-844 (sized, normalizeMeta)`)
- **What it is for:** the "wire census", a measurement instrument. For each executed statement it compares each output column's declared MIR label with the driver's own `getColumnTypeName`. To make the two comparable, it folds every driver's spellings into DuckDB-family names:
  - Postgres: `INT4`/`BPCHAR`/`JSONB`/`_int4`, plus sizing a bare `numeric`;
  - Databricks: `STRING`/`VARIANT`;
  - Snowflake: `NUMBER`/`OBJECT`;
  - BigQuery: `INT64`/`FLOAT64`/`DATETIME`/`BIGNUMERIC`;
  - MariaDB/MySQL: `LONGTEXT`/`DATETIME`/`BIGINT UNSIGNED`;
  - ClickHouse: `Nullable(..)`/`Tuple`/`DateTime64`/`Int128`;
  - SQLite: `FLOAT` and `NUMERIC` as NULL;
  - Trino: `ROW`.

  It also accepts each database's own "carrier" pairs, and it watches DuckDB's all-NULL INTEGER columns (:317, :488).
- **Who calls it:** `Executor.executePrepared` (:325) on every production statement. The probe is failure-isolated and changes no result. Its counts are consumed by the PCT `ChannelB*` lanes and `PctCensusGate`, which pin `wireDivergeCount` and `wireAdoptPendingCount`.
- **Why it is a leak:** a per-database type-name table lives in `exec/`.
- **Where it belongs:** per dialect, or per driver beside `DriverCells`: `wireTypeName(String driverName)` and `wireCarrierAccepts(SqlType label, String meta)`.
- **Size:** about 140 lines move.
- **Coupling:** as in group 5.

**10. `Executor.pureOfSqlType` driver type-name table** (`exec/Executor.java:1062-1085`, fed at :945; `exec/GridProbe.java:78`)
- **What it does:** maps a result column's type NAME (parameters stripped) to a Pure primitive. The cases are a union of DuckDB (`HUGEINT`), Postgres (`BPCHAR`), Spark and BigQuery (`STRING`), and `TEXT`.
- **Where it drives behaviour:**
  - dynamic-pivot column types (`pivotColumnType`, loud);
  - grid typed columns (`GridProbe.probeTypedColumns`, where null falls back to Any);
  - PCT deferred-TDS render (`StatementExecutor.java:2096-2102`, via `Render.resolveAllDeferredTds`).
- **Why it is a leak:** it is a per-driver name table. Reading the code shows names it does not cover:
  - Postgres reports `int4`/`int8`/`float8`/`bool`, which `SqlTypeCensus.normalizeMeta` folds but this table does not;
  - ClickHouse reports `Nullable(Int64)`, which becomes `NULLABLE` once parameters are stripped;
  - BigQuery reports `INT64`/`FLOAT64`;
  - Snowflake reports `NUMBER`.
- **Where it belongs:** switch on `md.getColumnType` (`java.sql.Types`), as `WireTypes.sqlTypeOf` already does, or `SqlDialect.pureTypeOfColumn(String name, int jdbcType)`.
- **Size:** about 25 lines.
- **Coupling:** `ErrorShapeGuardrailTest:186` (DEFAULT_LITERAL_FALLBACKS history), `JavaEvalLedgerTest` EVICT_NAMES `Executor.java`, `JdbcSurfaceCensusTest`, `RawSqlLedgerTest` `GridProbe.java=1`.

**11. PctProbe name-based temporal type sniff** (`exec/PctProbe.java:40-45`)
- **What it does:** the LIMIT-0 probe types a column as DATE if its type name is `DATE`, as TIMESTAMP if the name starts with `TIMESTAMP`, and as VARCHAR otherwise.
- **Why it is a leak:** this assumes ANSI or DuckDB names. ClickHouse `DateTime64`/`Date32` and MariaDB or BigQuery `DATETIME` fall through to VARCHAR. It feeds the PCT render (`StatementExecutor.java:2100`).
- **Where it belongs:** `java.sql.Types` codes, or the dialect method from group 10.
- **Size:** about 6 lines.
- **Coupling:** `ArchitectureTest:744` (`PctProbe`, 1), `JavaEvalLedgerTest:1093`, `JdbcSurfaceCensusTest`.

### LEAK-RAW

**12. Raw-H2 adaptation: `CsvSeed.adaptRaw` and its callers** (`setup/CsvSeed.java:251-255`; callers `StatementExecutor.java:2846-2848, 2927` (executeInDb), `exec/SetupRunner.java:31`, `PlanMaker.java:179`)
- **What it does:** corpus and test-data SQL authored in H2 runs through `dialect.rawH2IsNative() ? sql : RawSqlBoundary.h2ToDuckDb(sql, dialect.rawTarget())`.
- **Why it is a leak:** the target is decided by a ternary on an H2-identity flag (only `H2.java:174` returns true) outside the dialect. The rewrite is a shared regex translator chosen by a `Target {DUCKDB, POSTGRES}` enum. In addition, `SqlDialect.rawTarget()` defaults every other dialect (MariaDB, Trino, ClickHouse, Snowflake, ...) to DUCKDB, which is a defaulting fallback.
- **Where it belongs:** `SqlDialect.adaptCorpusH2(String sql)`. It would be the identity on H2, call RawSqlBoundary on DuckDb and Postgres, and throw on the others. That deletes `rawH2IsNative()` and `rawTarget()`.
- **Size:** about 15 lines, plus one override per dialect.
- **Coupling:** `DialectBoundaryTest.RAW_H2_CALLERS` `CsvSeed.java=1`; `RawSqlLedgerTest` `CsvSeed.java=1`; the `RawSqlBoundary` contract header.

### LEAK-CONN

**13. StorelessRuntime in-process connection spec switch** (`core/src/main/java/com/legend/test/StorelessRuntime.java:72-83`)
- **What it does:** a `DatabaseType` switch emits the connection-grammar spec and auth that declares an in-process session: `DuckDB { }`/`Test`, `LocalH2 { }`/`DefaultH2`, `SQLite { }`/`Test`. It also re-lists which types are servers (Postgres, MariaDB, MySQL).
- **Why it is a leak:** this is per-database connection knowledge outside `Sessions`. It is the inverse of `Sessions.openingFor` and duplicates `Sessions.inProcess`.
- **Where it belongs:** a per-database connector method such as `Connector.inMemorySpecification()`, or a `Sessions` method beside `openingFor`.
- **Size:** about 15 lines.
- **Coupling:** consumers are harness-only: `pct` `PctBackend`/`CloudLane`/`ChannelB`/`PctExecuteNative`, and about 15 core tests (`AssertErrorNativeTest`, `AuditRound3Test`, `AuditRound5Test`, exec tests).

Neither registry is a per-database object yet. `BulkLoad` and `DriverCells` beside the driver are the only per-database objects so far.

## Misses (database-specific code the scanner did not flag)

1. **`exec/DynamicPivot.java:89-94`.**
   - **What:** in the pivot-key literal switch, `BigDecimal when integral` covers Postgres delivering HUGEINT as NUMERIC(38), and `BigInteger when integral` is commented "ClickHouse delivers an Int128 ... as a BigInteger".
   - **Why it matters:** driver-carrier decoding sits in generic exec code and bypasses `dialect.normalize(v, type)`, which `Executor` uses (:796).
   - **Fix:** normalize the key through the dialect before the switch.
   - **Coupling:** `JavaEvalLedgerTest` pins the file at 112 lines. Only :115 was flagged.
2. **The DuckDB result vocabulary in lowering, unflagged sites:**
   - `CanonicalRenderSql.java:934, 938, 991` (`'OBJECT'`, `'NULL'`);
   - `lowering/Scalars.java:2656-2657` (`JSON_TYPE = 'ARRAY'`);
   - `lowering/CollectionLanes.java:354-355` (`JSON_TYPE <> 'NULL'`);
   - `lowering/LiteralSpelling.java:232-233` and `lowering/Fold.java:1300-1301` (`TYPEOF(e) = 'DATE'`).

   These are DuckDB's typeof names; `MariaDb.java:2313` walls TYPEOF because "its type names are DuckDB's". They belong in group 4's typed MIR predicate.
3. **`exec/H2Settings.java:44-50`.** H2's session settings (NON_KEYWORDS, `MODE=LEGACY`, `DEFAULT_NULL_ORDERING`) are a public JDBC-URL suffix. Apart from `Sessions`, it is spliced into hand-built `jdbc:h2:mem:` URLs at:
   - `pct/.../PctBackend.java:62`;
   - `spec/.../MinimalCorpus.java:509, 592` and `H2Verify.java:235`;
   - `core/src/test`: `StressSuites.java:89`, `PureV1ApiTest.java:557`, `PlanMakerTest.java:409`, `PlanRunnerTest.java:234, 311` and `RowLoadTest.java:154`.

   It belongs on an H2 connector, for example `H2Connector.open(name)`. `JavaEvalLedgerTest:1092` names it.
4. **`sql/dialect/SqlDialect.java:67-75`.** `rawH2IsNative()` is a capability flag that is H2's identity in disguise: only `H2.java:174` returns true. `rawTarget()` defaults every non-H2, non-Postgres dialect to `RawSqlBoundary.Target.DUCKDB`. The consumer is `CsvSeed.java:253-254`, group 12.
5. **`test/ServiceTestRunner.java:419` and `setup/CsvSeed.java:233-243`.** Test data travels only in a `LocalH2` connection specification, whatever the declared database type:
   - `ServiceTestRunner` builds `new ConnectionSpecification.LocalH2(null, csv, null)` with the `sessionType` of any database;
   - `CsvSeed.declaredSteps` reads test data from `LocalH2` alone.
6. **`exec/Executor.java:760-768`.** An Array-typed cell arriving as `byte[]` (H2's JSON carrier) is decoded in generic exec code, before `dialect.normalize` at :796. It belongs in `H2.normalize`.
7. **Guard blind spots that hide this slice's leaks:**
   - `DialectBoundaryTest.java:116-118`: the constructor regex omits MariaDb, MySql, Trino and ClickHouse. `Databases.java:55-61` builds those four unseen; the pin says 7, the real count is 11.
   - `DialectBoundaryTest.java:135`: the `DatabaseType` regex covers only H2, DuckDB and Postgres, so `Sessions.java:120` (MariaDB, MySQL) is invisible.
   - `DialectBoundaryTest.java:139-141`: the name regex lacks Snowflake, BigQuery, MariaDb, MySql, Trino and ClickHouse. It counts 2 of SqlTypeCensus's roughly 13 identity sites.
   - `SqlTextRatchetTest.java:55-60`: `SQL_SHAPE` does not match `create schema`, so `StatementExecutor.java:2951` (group 1) is unpinned.
8. **Checked and not leaks** (recorded so they are not re-chased):
   - `exec/VerdictBatch.java:192-201` matches our own `frame_` aliases inside vendor messages; this is database-neutral.
   - `lowering/DateFormats.java:99-104` uses DuckDB strptime codes (`%g`, `%b`) as internal token keys that are mapped at once to typed `DateFmt.Part`.
   - `exec/WireTypes.java:204-219` maps standard `java.sql.Types` and is database-neutral, though driver drift is possible (MariaDB `TINYINT(1)`/BIT).
   - `SqlTextVerdicts.java:155` decides "foreign dialect" against `Databases.REPLAY_ORACLE`, not a literal.
   - No `instanceof` on a dialect class, no JDBC-URL prefix test and no vendor SQLState or message matching was found in these packages (grepped).
